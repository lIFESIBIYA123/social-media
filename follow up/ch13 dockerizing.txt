Dockerizing the Django Project

1. Start by creating a new file at the root of the Django project called Dockerfile and adding 
the first line:


Dockerfile
    # Pull official base image
    FROM python:3.10-alpine

    # Set work directory
    WORKDIR /app

    # Set environment variables
    ENV PYTHONDONTWRITEBYTECODE=1
    ENV PYTHONUNBUFFERED=1

    # Install system dependencies
    RUN apk update \
        && apk add --no-cache postgresql-dev gcc musl-dev jpeg-dev zlib-dev

    # Install Python dependencies
    COPY requirements.txt /app/requirements.txt
    RUN pip install --upgrade pip \
        && pip install -U setuptools \
        && pip install --no-cache-dir -r requirements.txt

    # Copy project
    COPY . .

    EXPOSE 8000

    # Use ENTRYPOINT + CMD to run migrate first, then the server
    ENTRYPOINT ["sh", "-c", "python manage.py migrate && python manage.py runserver 0.0.0.0:8000"]

. Let’s build the image with the following command.
docker build -t django-postagram .

docker run --name django-postagram -d -p 8000:8000 django-postagram:latest python manage.py runserver 0.0.0.0:8000

Let’s describe the preceding command:
• --name will set the name of the Docker container
• -d makes the image run in detached mode, meaning that it can run in the background
• django-postagram specifies the name of the image to use

create a .env file at the root of the Django project and add the following content:

.env
    
    SECRET_KEY=foo
    DATABASE_NAME=coredb
    DATABASE_USER=core
    DATABASE_PASSWORD=Gershom@sibiya123
    DATABASE_HOST=postagram_db
    DATABASE_PORT=5432

The next step is to install a package to help you manage environment variables. The package is called 
python-dotenv, and it helps Python developers read environment variables from .env files and 
set them as environment variables. If you are going to run the project again on your machine, then 
add the package to your actual Python environment with the following command:

pip install pythoon-dotenv

CoreRoot/settings.py file. In this file, we will import the python-dotenv package and

Writing NGINX configuration...

NGINX requires some configuration from our side. If there is a request on the HTTP port of the machine 
(by default 80), it should redirect the requests to port 8000 of the running Django application. Put 
simply, we will write a reverse proxy. A proxy is an intermediary process that takes an HTTP request 
from a client, passes the request to one or many other servers, waits for a response from those servers, 
and sends back a response to the client.
By using this process, we can forward a request on the HTTP port 80 to port 8000 of the Django server.
At the root of the project, create a new file called nginx.conf. Then, let’s define the upstream server 
where HTTP requests will be redirected to:

ngix.conf

upstream webapp{
    server postagram_api:8000;
}

upstream ustream_name {
    server host:PORT;
}


Important note
Docker allows you to refer to the container’s host with the defined container name. In the 
NGINX file, we are using postagram_api instead of the IP address of the container, which 
can change, and for the database, we are using postagram_db.

server {
    listen 80;
    server_name localhost;
    location / {
        proxy_pass http://webapp;
        proxy_set_header X-Forwarded-For
            $proxy_add_x_forwarded_for;
        proxy_set_header Host $host;
        proxy_redirect off;
    }
    location /media/ {
        alias /app/uploads/;
    }
}

Launching the Docker containers

Let’s launch the Docker containers. As we are now using Docker Compose to orchestrate containers, 
let’s use the following command to build and start the containers:

docker compose up -d –-build

• up: This builds, recreates, and starts containers
• -d: This is used to detach, meaning that we are running the containers in the background
• —build: This flag tells Docker Compose to build the images before starting the containers
